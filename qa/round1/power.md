# Lumen r1: power-user review ("power")

Persona: long-time MPC-HC / mpv / VLC user, keyboard first. Build: `build-r1\Lumen.exe`. Data dir: `%TEMP%\lumen-qa\data-power`. Every instance was started with `--new-instance --automation --data-dir`. Screenshots are in `%TEMP%\lumen-qa\round1\shots-power\` (the `_scratch\` subfolder holds the raw crops).

**Short version:** the engine is fast. The window appears in about 80 ms and the file is loaded in about 300 ms. Frame stepping is exact, the seek preview is good, and CPU use is low. The playlist and resume logic around it, though, keeps playing the wrong thing. I re-opened a file I had finished and Lumen played a different file. I passed a path that does not exist and Lumen played a random video from that folder. In a series, Previous does nothing. On top of that, the window is sized for the previous video, and Space stops working after any click on the control bar. I would not switch from MPC-HC yet.

## Top 5

1. **Re-opening a watched file plays the wrong thing, and Previous is broken (Blocker).** Lumen writes a watch-later entry at the very end of the file (EOF). After that, opening the file puts you on its last frame. If the folder has a next file, Lumen silently jumps to it. Examples: `Chaptered Demo` opened `Long Seek Test`, and `S01E02` opened `S01E03`. In a series, P, PgUp and the Previous button send you straight back to the episode you were on (P01, P02).
2. **The window is fitted to the previous file's size (Major).** Every file after the first is fitted using the last file's dimensions. A 720p file ends up in a 1080p-sized window, a vertical clip in a landscape window, and a landscape file in a tall portrait window (P04).
3. **Space is taken over by the last-clicked button (Major).** Click any control-bar button once, for example the subtitles panel button, and Space from then on triggers that button again. Playback does not pause (P05).
4. **Bad input gets bad or no handling (Major).** A path that does not exist plays a different file from the folder (P03). An `.m3u` playlist fails with "unrecognized file format" (P06). Broken or fake files show a raw English mpv string for 1.2 s, then leave a blank player (P11).
5. **Keyboard actions give no feedback (Major).** Cycling audio or subtitle tracks (A, V, Shift+V), jumping chapters (Shift+PgUp/PgDn), seeking with the arrows, and pressing N at the end of the queue show no on-screen message. A-B loop shows the same toast for "A set", "B set" and "cleared", and draws no markers on the seek bar. In mpv or MPC-HC you always know which track or chapter you landed on (P07–P10, P19).

## What works well (credit where due)

- **Startup:** the window appears 71–96 ms after `Start-Process` (polled). Trace for the 4K file: `window shown` 83 ms, `mpv ready` 102 ms, `file loaded` 296 ms. That beats VLC and matches MPC-HC.
- **CPU:** 720p playing about 5.5% of one core; paused 0.0%; library idle 0.0%.
- **Seeking:** frame step `.` and `,` is exact (59.700 → 59.733 → 59.767 → 59.733). Arrow seeks are exact ±10, ±3 and ±60 s. Wheel over the seek bar seeks ±5 s; wheel over the video changes volume.
- **Seek-bar preview:** appears within 150 ms with the right frame (hovering 5:21 shows "321"), plus a chapter-name tooltip and chapter tick marks.
- **Subtitles and unicode:** the sidecar `.srt` loads automatically, and the unicode / «» / 日本語 path works in the title, history and playback.
- **Resume:** works for files stopped mid-way (4:44 → 4:45). Maximized state and placement are restored.
- **Fullscreen:** F, F11, Alt+Enter, double-click and Esc all work. The controls auto-hide after about 2 s when the mouse is over the video, and the video then fills 2560×1440.

## Not tested / notes

- **Second-file hand-off to a running instance:** skipped. Other Lumen processes (other reviewers) were running the whole time, and the single-instance path would `FindWindowEx` any of them.
- **Minimize/restore:** not exercised, because it could change the owner's foreground window. Maximize and restore through the caption buttons work.
- **Cursor hiding in fullscreen:** not verifiable with PrintWindow captures. The code path exists (Host.cpp:514, 1048).
- **Record (R):** not pressed, because it writes to `%USERPROFILE%\Videos\Lumen`.
- **Volume:** stayed at 0 or muted the whole time, except one accidental ↑ (5% for under 1 s on `Long Seek Test`), which was reverted immediately.
- **Files created outside the data dir:** one snapshot, `C:\Users\wheny\Pictures\Lumen\Chaptered Demo (1080p)-00_00_27.933.png`. The second snapshot is in `data-power\shots`.
