## 1. Crossfade between songs

### What was built

- **Settings > Audio > Output**, under "Gapless playback":
  - "Crossfade between songs", off by default;
  - "Crossfade length", 1–12 s, default 5;
  - "Only between different albums", on by default, so albums meant to be gapless stay gapless.
    Album tags decide (case and spaces ignored); without tags, one folder is one album.
- **How it overlaps.** mpv plays one file at a time. The main instance keeps everything that
  belongs to a file: the queue, history, tracks, filters, the title and the media session. A
  short-lived second, audio-only mpv instance (`src/audio/Crossfader.*`) plays the old song's
  last seconds:
  1. About 3 s before the fade it opens the ending song paused at S = end − fade − 1.85 s, with
     main's filters, device, Replay Gain and volume. The worker reads the album tags here.
  2. At S it starts silent, early by the start delay it learned last time. While still silent
     it is nudged into step with the main instance by short speed changes. Measured offset
     after this: 0.0 ms in the three runs whose trace survived (16–25 ms before the early
     start and the speed nudging).
  3. For 0.25 s both instances play the same audio. Main fades it out and the helper fades it
     in; the two gains always add up to 1.
  4. At the fade start, main moves on to the next song with `playlist-next`. That song is the
     one QueueNext already handed to mpv, prefetched, so the queue, title, history and SMTC
     move on through the existing `kChangeAdvance` path. The new song fades in and the helper's
     tail fades out with equal-power curves.
  5. The helper ends with its file and is destroyed. Gains are mpv's `volume-gain`, never the
     user's volume.
- **Why not a second instance for the incoming song?** The incoming song would then have to
  move from the helper to main at full volume, which glitches. And for its first seconds the
  queue, tracks and filters would belong to the wrong instance. The old song's tail needs none
  of that.
- **Edge cases:**

  | Case | What happens |
  |---|---|
  | Next, Previous or another file during a fade | The tail and the new file ramp over 0.1 s instead of cutting. |
  | Seek during a fade | The tail fades out in 0.1 s and the playing song comes up to full volume. |
  | Seek before the fade | The plan is dropped and armed again if there is still time. |
  | Pause during the fade | Both instances pause, and the fade resumes where it stopped. |
  | Pause in the last 2 s before the fade | No fade this time: the song ends gaplessly. |
  | Volume and mute | Mirrored to the helper. |
  | Speed | Mirrored to the helper; the ramps follow content time. |
  | The last song, Repeat One, Stop after each | No next file is queued, so there is no fade. |
  | Repeat All | The last song fades into the first. |
  | Shuffle | Fades into whatever the shuffle queued. |
  | Videos | Never fade: neither a file with a video track nor a video extension on either side. Streams never fade either. |
  | Exclusive mode, passthrough | No fade, because one stream owns the device. |
  | mpv went on by itself earlier (a too-long duration estimate) | The worker checks the path before `playlist-next`, so no song is skipped. |
  | A song shorter than twice the fade | It gets at most half its length minus 1 s. |
- **Settings reach Player** as the pseudo options `user-data/lumen/crossfade` (seconds, 0 = off)
  and `user-data/lumen/crossfade-albums`. Player reads them in its own functions
  (`CrossfadeOption`, `CheckCrossfade`, `CancelCrossfade`, `SyncCrossfade`) and never passes
  them to mpv. Live changes come through the normal `MpvOptionFor` path.

### How to use

Settings > Audio > "Crossfade between songs". Play an album queue: songs of the same album stay
gapless, and the change of album crossfades. With the album toggle off, every change crossfades.

`tools\r7mu-xf-analyze.py` measures each test tone's level every 50–250 ms and looks for
sample jumps (clicks). The queue index is logged every 150 ms through `command.ps1 state`. All
files are in `%TEMP%\lumen-qa\r7mu-xf`: `<run>.wav`, `<run>-state.txt`, and `<run>-levels.txt`
or `.png` for some runs.

The volume during a fade was checked only as mute and by reading the code. It uses the same

### Performance

- Off: nothing exists, no thread and no timer. `CheckCrossfade` returns on its first compare in
  each time update.
- One transition, measured as process CPU over the last 13 s of a song, 4 runs each:
  - without crossfade, 281 ms;
  - with it, 414 ms.

  So a fade costs about 0.13 s of CPU per song change (≈1 % of a core around it). This includes
  creating and destroying the helper, decoding the tail and the worker's ramps. The ramps run at
  200 steps/s during the 0.25 s handoff and 50 steps/s through the fade. Before the 50 Hz change
  it was 266 → 528 ms. Files: `r7mu-perf-xf.txt`, `r7mu-perf-xf2.txt`.
- The UI thread never waits on the worker. The worker's synchronous mpv calls run on its own
  thread, so no reply events wake the UI.

## 2. Visualizer in the music view

### What was built

- The hidden `audio.visualizer` setting is now a visible row in Settings > Audio > Effects, with
  the four styles of components/Audio_Visualizer:
  - **Spectrum:** 48 bars on a log scale from 40 Hz to 16 kHz, with falling peak marks.
  - **Spectrometer:** spokes around a round copy of the cover.
  - **Scope:** an oscilloscope trace triggered at a rising zero crossing, with automatic gain.
  - **Waveform:** a loudness history scrolling left; older columns fade.
- **Placement.** It takes the cover's place while a song plays, as the setting has always said.
  The blurred cover stays as the backdrop. The bar styles are 1.5× the cover's width, at the
  same height, so the title does not move. A pause brings the cover back with a 0.22 s fade.
  It works next to lyrics too, in the left half.
- **Look.** Monochrome: white mixed into `videoBg`, like the title, because the view is dark in
  both themes.
- **Source:** WASAPI process loopback (`AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`,
  `PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE`) for Lumen's own PID. It never hears other
  apps. `mmdevapi.dll` is loaded with `LoadLibraryEx` only when the visualizer is on, so
  build.bat is unchanged. On Windows older than 10 2004 (build < 19041), the row is hidden and a
  quiet note says why: "Visualization needs Windows 10 version 2004 or later". If activation
  fails at runtime, the cover simply stays.
- **Threading** (`src/audio/LoopbackCapture.*`, `src/audio/Spectrum.h`):
  - Capture, FFT (2048, Hann), bands, smoothing, peaks, scope and waveform all run on the
    capture thread.
  - The UI only copies a 2.6 KB frame (no allocation) and draws it.
  - Each frame posts one repaint; the next is posted only after the paint took the previous one.
    That caps the rate at 60/s, and about 36/s were analysed in practice.
- **No work when not needed:**

  | State | Behaviour |
  |---|---|
  | Setting off | No thread. |
  | Paused, stopped or ended | The capture client is stopped and the thread is parked on an event. |
  | Not drawn (another screen, a video, minimized) | No frame is taken for 0.5 s, so the thread parks itself; the next paint of the view wakes it. |

### Pre-volume tap (the brief's question)

Process loopback hears Lumen after both volumes. The probe measured it:
- a float sine at amplitude 10⁻¹⁵ arrives intact (ratio 1.0025 after 44.1 → 48 kHz);
- the Windows session volume is applied before the tap (0.5 → amplitude ×0.25; 0 → silence);
- mpv's software volume is applied in the samples, so volume 0 gives zeros.

So a true pre-volume tap is not available. The fix uses the float headroom: while the
visualizer is on, Player sends volume 0 to mpv as `0.001` (`Player::kTapVolume`, gain 10⁻¹⁵,
−300 dB). That is digital silence at any DAC, yet the float samples keep the waveform. Player
reports 0 to the UI and settings, and mpv reporting exactly 0 from anywhere is corrected the
same way. The visualizer divides by mpv's gain (`Player::OutputGain()`), so it looks the same at
every volume. The tap is off whenever the visualizer is off, and nothing else changes.
Mute still gives zeros, so the visualizer rests while muted. The session volume is not
compensated: a Lumen slider lowered in the Windows mixer makes the bars lower.

Data at volume 0, from the tree dump (`MusicView … viz=3 frames=134 captured=161280 level=0.58
top=0.66`); screenshots in `r7mu-shots`: `viz-spectrum.png`, `viz-scope.png`,
`viz-waveform.png`, `viz-spectrometer.png`, `viz-live-scope.png`, `viz-live-paused.png`.
Before the fix the same dump read `level=0.00`.

### How to use

Settings > Audio > Effects > "Visualization": pick a style and play a song. It changes live.

### How it was verified

## 4. Left out, and why

- **Next/Previous during a fade still starts on a cut** of the song that was fading in. Player's
  `Open` replaces the file at once on the UI thread. A fade-out before `loadfile` would delay
  every manual Next, so only the ramps after it were softened.
- **The volume mirror was not measured at a non-zero volume:** that would be audible. Mute and
  the code path were checked instead.
- **Minimized was checked only by reading the code:** `Host::Render` returns for iconic windows,
  so the view isn't painted and the thread parks. Background test windows are cloaked and can't
  be minimized. The hidden-screen case, which uses the same mechanism, was measured.
- **Mute does not keep the visualizer moving:** mpv's mute writes zeros, and faking it would
  have changed what mute means.
- **The session volume** (Windows mixer) is not compensated in the visualizer levels.
- **Frame rate:** the visualizer is capped at 60/s and runs at about 36 analysed frames/s in
  practice. Each frame repaints the whole window, because the host has no partial invalidation;
  that is outside this file scope.
- **Repeat One does not crossfade into itself.**
- The crossfade's trace lines (`xfade[pid] …` under LUMEN_TRACE) go to the shared
  `%TEMP%\lumen-trace.txt`, which other agents' runs truncated during this round. The audio
  recordings, not the trace, are the evidence.
