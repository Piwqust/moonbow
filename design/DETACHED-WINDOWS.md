# Отдельные окна для любых элементов: проект

## Состояние на 21.11.2026

Владелец выбрал: **копия** (главное окно не меняется), окна **независимые** (без владельца, без кнопки
на панели задач, не сворачиваются с главным), **перетаскивание позже**, панели — **все**.

Сделано (этапы 1–3):

- `src/app/player/AudioFeed.*` — один захват звука на весь Moonbow; экран музыки, окно индикаторов и
  каждое отдельное окно берут кадры из него. Общие пики, лампочки клипа, история LUFS и сброс. Новый
  кадр рассылается, только когда все окна нарисовали предыдущий: иначе при многих окнах Windows отдаёт
  WM_PAINT по порядку окон, и последние не рисовались совсем.
- `src/app/player/DetachedWindows.*` — каталог из 15 панелей, универсальное окно, `windows.json`
  (какие окна открыты, где стоят, «поверх всех», «без заголовка»), возврат окна на видимый монитор.
- `src/app/player/DetachedPanels.*` — управление, полоса перемотки, обложка, «Сейчас играет»,
  визуализация (полосы, волна, осциллограф), текст песни.
- Карточки `MetersView.cpp` стали самостоятельными; «Индикаторы звука» — сетка из них.
- Входы: правый щелчок в плеере и меню приложения → «Отдельные окна»; Ctrl+K; в сетке индикаторов у
  каждой карточки «Открыть в отдельном окне».
- В окне: перетаскивание за любое место, кроме элементов управления; двойной щелчок — полный экран
  (Esc — выход); правый щелчок — меню панели и окна; у обложки окно держит квадрат.
- Автоматизация: `window open|close <id>`, `window list` (`tools/dev/command.ps1`).

Не сделано: несколько панелей в одном окне по выбору пользователя (есть только готовая сетка
индикаторов), заголовок, появляющийся при наведении (вместо него переключатель «Показывать
заголовок»), перетаскивание между окнами (этап 4).

Ниже — исходный проект.

---

Черновик от 21.11.2026. Цель: любой элемент плеера (полоса перемотки, обложка, VU-индикаторы, громкость
LUFS, спектр, стерео, текст песни, очередь…) можно вынести в своё окно, поставить куда угодно, хоть на
второй экран, и Moonbow запомнит это до следующего запуска.

## 1. Что есть сейчас

`src/app/player/DetachedWindows.cpp` умеет ровно два окна:

| Окно | Чем включается | Что внутри |
|---|---|---|
| «Управление плеером» | `interface.controlsWindow` | `SeekBar`, время, кнопки, громкость (собрано вручную) |
| «Индикаторы звука» | `interface.metersWindow` | `MetersView`: 5 карточек (VU, LUFS, уровни, стерео, спектр), видимость каждой — `interface.metersVu` и т. д. |

Что мешает обобщить это как есть:

1. **Каждое окно — свой класс.** Новый элемент = новый класс, новая настройка, новая строка в `Sync()`.
2. **Звук анализируется отдельно в каждом месте.** У экрана музыки свой `LoopbackCapture`, у окна
   индикаторов — свой (`Feed` в `MetersView.cpp`). Захват привязан к одному `HWND` (сообщение о
   перерисовке уходит одному окну). Пять индикаторов в пяти окнах — пять потоков захвата и пять БПФ на
   одном и том же звуке. Тап сигнала (`Player::SetSignalTap`) различает слушателей битовой маской 1 и 2.
3. **Общее состояние живёт внутри вида.** История LUFS, удержанные пики, лампочки клипа, кнопка «Сброс»
   лежат в `Feed` окна индикаторов. Если вынести график LUFS и уровни в разные окна, сброс должен
   действовать на оба.
4. **Окна не помнят место и размер.** Каждый раз открываются по центру с размером по умолчанию.
5. **Обложка и VU экрана музыки не отдельные виджеты**, а части `MusicView::Paint`.

## 2. Модель: панель, окно, раскладка

Три понятия вместо «окно = класс»:

- **Панель** — элемент, который умеет жить где угодно: виджет плюс описание (имя, иконка, размер по
  умолчанию, минимальный размер, нужна ли пропорция, нужен ли звук). Панели регистрируются в одном
  каталоге.
- **Окно панелей** — одно универсальное окно (`PanelWindow`, вырастает из нынешнего `DetachedWindow`).
  В нём одна панель или несколько. Окно не знает, что в нём лежит.
- **Раскладка** — список открытых окон: какие панели, где стоит окно, его размер, монитор и параметры
  («поверх всех», «без заголовка»). Хранится в `windows.json` рядом с `ui.json` и восстанавливается при
  запуске.

Нынешние два окна становятся просто готовыми раскладками: «Управление плеером» = одно окно с панелью
`controls`; «Индикаторы звука» = одно окно с пятью панелями в сетке. Их пункты в настройках остаются и
открывают эти пресеты.

### Копия или перенос

Рекомендация: **вынос = дополнительная копия**. Главное окно остаётся как было: полоса перемотки на месте,
обложка на месте. Причины:

- главное окно не ломается: никаких дыр в панели управления, никакой отдельной логики «вернуть на место»;
- закрыл окно — элемент просто исчез с того экрана, где мешал, ничего не надо «возвращать»;
- для индикаторов это и есть то, что нужно: смотреть VU на втором мониторе, пока главное окно свёрнуто
  или занято медиатекой.

Если потом понадобится «убрать из главного окна» (например, прятать полосу перемотки, когда она вынесена),
это отдельная галочка у конкретной панели, а не общее правило.

## 3. Каталог панелей

| id | Панель | Откуда берётся | Особенности окна |
|---|---|---|---|
| `controls` | Управление плеером (как сейчас) | `ControlsWindow::Build` | высота фиксирована, ширина свободная |
| `seekbar` | Полоса перемотки (волна для музыки) + время | `SeekBar` | высота фиксирована, ширина свободная |
| `cover` | Обложка (на паузе и без неё — та же картинка) | выделить из `MusicView` | квадрат, тянется за угол с сохранением пропорции, двойной щелчок — полный экран |
| `nowplaying` | Обложка + название + исполнитель | выделить из `MusicView` | |
| `vu` | Пара VU-индикаторов | `VizPaint::VuPair` | сама выбирает «рядом / друг над другом» (уже умеет) |
| `vu.left`, `vu.right` | Один индикатор | `VizPaint::VuMeter` | пропорция 1,6 : 1 |
| `loudness` | LUFS (EBU R128) + график | `LoudnessCard` | |
| `levels` | Уровни RMS / пик | `LevelsCard` | |
| `stereo` | Гониометр, корреляция, баланс | `StereoCard` | |
| `spectrum` | Спектр с сеткой | `SpectrumCard` | |
| `viz` | Визуализация экрана музыки (полосы, волна, осциллограф) | `VizPaint` | |
| `lyrics` | Текст песни | выделить из `MusicView` | |
| `queue` | Очередь | `panel::BuildQueueTab` (уже переиспользуется в доке) | |

Карточки окна индикаторов уже почти панели: у каждой свой `Paint`, своё меню и общий `Feed`. Их надо
только отвязать от `MetersView`.

## 4. Как пользователь выносит элемент

Четыре входа, один механизм (`OpenPanel(id)`):

1. **Правый щелчок по элементу → «Открыть в отдельном окне».** Главный способ: на обложке, на полосе
   перемотки, на стрелках экрана музыки, на каждой карточке окна индикаторов.
2. **Меню приложения → «Окна»**: список всех панелей с галочками (открыта / нет) и пресеты («Индикаторы
   звука», «Управление плеером»).
3. **Ctrl+K**: «Открыть окно: VU-индикаторы» и т. п., по одной команде на панель.
4. **Перетаскивание** (второй этап): карточку из окна индикаторов тянешь за заголовок за пределы окна —
   появляется новое окно с ней. Бросаешь на другое окно панелей — она встаёт туда.

Закрыть: крестик окна, или тот же пункт с галочкой ещё раз.

## 5. Окно панелей

- **Заголовок 32–40 DIP** с именем панели, кнопками «поверх всех» и «закрыть». Для обложки и VU нужен режим
  **без рамки**: заголовок появляется только при наведении, окно таскается за любое место (как PiP:
  `PipOverlay` уже так умеет), края тянутся.
- **Пропорции:** у обложки и одиночного VU окно держит форму при растягивании (`WM_SIZING`, как в
  `MainWindow` для PiP).
- **Поверх всех окон** — у каждого окна своё (сейчас это одна общая `interface.metersOnTop`).
- **Окно не владеется главным.** Сейчас `o.owner = main`, поэтому вынесенные окна сворачиваются вместе с
  главным. Индикаторы на втором мониторе нужны как раз при свёрнутом главном. Предлагаю: без владельца,
  без кнопки на панели задач (`WS_EX_TOOLWINDOW`), а сворачивание главного их не трогает. Это стоит
  решить явно (раздел 10).
- **Клавиши плеера** работают в любом окне панелей (уже так).
- **Контекстное меню окна:** меню самой панели, затем «Поверх всех окон», «Без заголовка», «Закрыть окно».

## 6. Общий источник звука (`AudioFeed`)

Сейчас каждый потребитель создаёт свой `LoopbackCapture`. Нужен один общий сервис:

- **Один захват на процесс.** Создаётся, когда появляется первый подписчик, умирает с последним.
- **Анализ один раз за тик.** Каждый поток кадров считается однажды (RMS, пики, БПФ, LUFS, гониометр), а
  подписчики берут готовый `VisualFrame` с номером кадра. Сейчас `Take()` забирает данные: два читателя
  делили бы кадры между собой.
- **Подписка вместо `HWND`.** Захват шлёт «есть новый кадр» сервису, а сервис просит перерисоваться
  каждое окно, где есть подписанная видимая панель. Невидимые и свёрнутые не будят.
- **Общее состояние измерений** переезжает из `Feed` в сервис: история LUFS, удержанные пики и максимумы,
  лампочки клипа, сброс. Сброс в любом окне сбрасывает везде.
- **Тап сигнала** (`SetSignalTap`) — счётчик подписчиков вместо битовой маски.
- **Стрелки VU** (физика пружины) остаются у каждого вида: на одних и тех же кадрах они и так ведут себя
  одинаково, а общий объект связал бы их частоту кадров.

Это первое, что надо сделать: без этого уже два окна с индикаторами — двойная нагрузка.

## 7. Сохранение раскладки

`windows.json` в папке данных (рядом с `ui.json`):

```json
{
  "version": 1,
  "windows": [
    {"panels": ["vu"], "rect": [2600, 120, 900, 560], "monitor": "\\\\.\\DISPLAY2",
     "onTop": true, "frameless": true},
    {"panels": ["loudness", "levels", "stereo", "spectrum"], "grid": "meters", "rect": [...]}
  ]
}
```

- Координаты в DIP своего монитора плюс имя монитора. При запуске: если монитора нет или окно оказалось
  за краями всех экранов — сдвинуть на ближайший видимый (`MonitorFromRect`, `MONITOR_DEFAULTTONEAREST`).
- Сохраняется при перемещении и изменении размера (с задержкой, как `ui.json`) и при выходе.
- Окна открываются после первого кадра главного окна, чтобы не тормозить запуск (тот же приём, что с
  drag-and-drop).
- **Перенос со старых настроек:** `interface.controlsWindow = true` превращается в окно `controls`,
  `interface.metersWindow = true` — в пресет индикаторов с теми карточками, что были включены. Сами
  настройки остаются как переключатели пресетов в разделе «Отдельные окна».

## 8. Устройство кода

```
src/app/panels/
  PanelRegistry.h/.cpp   каталог: id, имя, иконка, размеры, пропорция, нужен ли звук, фабрика виджета
  PanelWindow.h/.cpp     универсальное окно (из DetachedWindow): заголовок, режим без рамки, пропорция,
                         поверх всех, меню, сетка из нескольких панелей
  WindowLayout.h/.cpp    windows.json: загрузка, сохранение, перенос старых настроек, OpenPanel/ClosePanel
src/audio/AudioFeed.h/.cpp  общий захват и анализ, подписки, общее состояние измерений
```

- Карточки из `MetersView.cpp` переезжают в `src/app/panels/` как отдельные панели, `MetersView`
  становится сеткой из них (пресет).
- Из `MusicView` выделяются `CoverView` и `NowPlayingView`. Экран музыки сам пользуется ими же, чтобы не
  было двух разных обложек.
- Автотесты: команда автоматизации `window open <id>` / `window close <id>` / `window list`, чтобы прогон
  экранов (`tools/dev/sweep.ps1`) снимал каждую панель отдельно на нескольких размерах.

## 9. Этапы

| Этап | Что | Видно пользователю |
|---|---|---|
| 1. Основа | `AudioFeed`; `PanelRegistry` + `PanelWindow` вместо двух классов; `windows.json` с местом и размером; перенос старых настроек | два нынешних окна запоминают место; индикаторы не грузят процессор вдвое |
| 2. Панели | каждая карточка индикаторов — своя панель; `vu`, `cover`, `seekbar`, `nowplaying`; пункт «Открыть в отдельном окне» в меню; меню «Окна»; команды Ctrl+K | можно вынести любой из этих элементов |
| 3. Окна | режим без рамки, пропорции, «поверх всех» у каждого окна; `lyrics`, `queue`, `viz`, одиночные `vu.left/right` | «виджеты» на рабочем столе |
| 4. Перетаскивание | вытащить карточку из окна → новое окно; бросить на окно → встать в него; свои пресеты раскладок | как вкладки в браузере |

Каждый этап отдельно собирается и тестируется. Этап 1 нужен всем остальным.

## 10. Что решить владельцу

1. **Копия или перенос** (раздел 2). Рекомендация: копия.
2. **Окна живут отдельно от главного или сворачиваются вместе с ним** (раздел 5). Рекомендация:
   отдельно, без кнопок на панели задач.
3. **Перетаскивание в первой версии или позже.** Рекомендация: позже (этап 4); сначала меню, оно проще
   и надёжнее.
4. **Какие панели нужны в первую очередь.** Предложение: VU, обложка, полоса перемотки и карточки
   индикаторов по одной.

## 11. Риски

- **Нагрузка.** Каждое окно — свой swap chain и свой цикл отрисовки. Индикаторы рисуют 60 кадров в
  секунду, поэтому замерить нужно с 5–6 открытыми окнами. Условие то же, что сейчас: без звука и на паузе
  0 мс процессора.
- **Потеря видеоустройства** (смена видеокарты, сон): каждое окно должно пережить `OnDeviceReady`, как
  нынешние два.
- **DPI и мониторы:** окно, перенесённое на монитор с другим масштабом, должно перестроиться (у `Host`
  это есть, но с режимом без рамки и пропорцией нужно проверить).
- **Фокус:** окна открываются без активации (`SW_SHOWNOACTIVATE`, как сейчас) и не забирают ввод у
  главного.
