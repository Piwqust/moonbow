## 6а. Проход по интерфейсу (после этапа 3)

Владелец сообщил о четырёх проблемах:
1. интерфейс просвечивает;
2. в полноэкранном режиме не редактируется очередь;
3. окно меняет размер при смене видео;
4. нижняя панель неудобно скрывается и показывается, у неё нет минимального вида, и она закрывает видео.

Два охотника за багами (отчёты в [qa/round4/](qa/round4)) нашли ещё 33 проблемы. Исправлено:

- **Просвечивание.** Каждое окно в каждом кадре заливает фон целиком, главное окно — всё, кроме прямоугольника под видео. Раньше прозрачными оставались отступ 8 DIP вокруг бокового меню и полосы, появлявшиеся после увеличения окна. Боковая панель плеера в полноэкранном режиме теперь непрозрачная и на всю высоту.
- **Размер окна.** «Подгонять окно под видео» по умолчанию стоит на «Никогда».
- **Панель управления.** Новая настройка «Вид панели управления»:
  - плавающая (по умолчанию) — скруглённая панель с отступами поверх видео;
  - во всю ширину;
  - минимальная — пауза, время, тонкая полоса перемотки, 40 DIP.

  Панель плавно уезжает при скрытии. Дрожание мыши на 5 px её не будит. Субтитры поднимаются над плавающей панелью.
- **Окно:**
  - подсказки больше не застревают; у нижних кнопок они появляются сверху, у свёрнутого меню — сбоку;
  - после «развернуть → полный экран → назад» не остаётся рамки;
  - развёрнутое окно не закрывает панель задач;
  - диалоги на окне 720×440 прокручиваются;
  - правый край списков снова кликается;
  - текущая папка в узкой шапке не теряется;
  - настройки в широком окне собраны в колонку;
  - на пустых страницах нет кнопок сортировки.
- **Плеер:**
  - очередь синхронизируется с подготовленным в mpv следующим файлом при каждой правке; удаление играющего файла и перемешивание исправлены, добавлен юнит-тест `play_queue`;
  - кнопки «Пропустить заставку» и «Следующая серия» не закрывают субтитры;
  - в «картинке в картинке» есть меню по правому щелчку;
  - подвал быстрых настроек компактнее в низком окне;
  - у всех строк очереди видна длительность;
  - боковая панель занимает не больше 45 % ширины;
  - подписи «вкл/выкл» в переключателях читаются.

**Не воспроизведено:** очередь в полноэкранном режиме, пункт 2 у владельца. Её пробовали воспроизвести я, оба охотника и исправитель, разными сценариями:
- перетаскивание, двойной щелчок, правый щелчок;
- при паузе и во время воспроизведения;
- после автоскрытия панели;
- после переключения полноэкранного режима.

Ответ `WM_NCHITTEST` над очередью — «клиентская область». Синтетический ввод не повторяет настоящую мышь: скрытие курсора, `WM_MOUSELEAVE`. Причину нашли в раунде 5: в полноэкранном режиме не работала боковая панель (FL-01, раздел 6б).

## 6р. Свой установщик вместо Inno (2026-10-22/23)

Решения владельца: свой Setup.exe на UI Lumen вместо Inno; версии пока только из локальных файлов;
полный офлайн-установщик. Сделаны все 4 этапа: механика (коммит e06325e) → экраны установщика →
версии и откат внутри Lumen → переход с Inno и упаковка.

- **Setup.exe = Lumen.exe + приложенные файлы** (`src/setup/Package.*`): после PE-образа идут
  libmpv и README блоками по 8 МБ, сжатые LZMS (встроенный в Windows Compression API, без
  библиотек), у каждого файла контрольная сумма FNV-1a (LZMS сам порчу не замечает: тест это
  поймал). Устанавливаемый Lumen.exe это первые байты самого установщика. Собирает
  `Lumen.exe --make-setup <out> <файлы>`; `tools/package-beta.ps1` кладёт его как
  `…-setup.exe` (~46 МБ, Inno был ~38 МБ; сборка ~20 с). Inno убран (`tools/installer/lumen.iss`
  остался в истории git).
- **Раскладка** (`src/setup/Installer.*`): текущая версия в `%LOCALAPPDATA%\Programs\Lumen` (пути
  ярлыков, закреплений, типов файлов и списка переходов не меняются), каждая версия в
  `versions\<версия>\`. Одинаковые файлы версий (libmpv) это жёсткие ссылки на один файл. Хранится
  текущая + 2 другие.
- **Любая версия на любую**: установщик сам определяет «установить / обновить / откатить /
  переустановить». Сначала полностью раскладывается `versions\<новая>`, потом файлы по одному
  подменяются; при сбое возвращается прежняя версия. Повреждённый установщик ничего не меняет.
- **Данные при смене версии**: `*.json` из `%APPDATA%\Lumen` копируются в `backups\<старая версия>`.
  При откате по умолчанию остаются текущие настройки (старый Lumen пропускает незнакомое); галочка
  «Вернуть настройки и медиатеку, какие были в Lumen X» возвращает прежние.
- **Окно установщика** (`src/setup/SetupWindow.*`, 720×500, тема, акцент и язык из настроек
  Lumen): приветствие с логотипом в мягком свечении и одной кнопкой «Установить»; «Параметры
  установки» (папка, «Открывать видео в Lumen по умолчанию», включено); обновление со стрелкой
  версий «0.1.0 → 0.2.0» и списком «Что нового»; возврат к прежней версии; «уже установлен» с тремя
  карточками (Открыть / Исправить / Удалить); удаление с галочкой «Удалить также настройки» (выключена);
  работа с кольцом прогресса вокруг логотипа и строкой этапа («Закрываем Lumen…», «Распаковываем
  файлы… 42 %»); «Готово» с рисуемой галочкой и кнопкой «Открыть Lumen»; ошибка с «Повторить» и
  «Ничего не изменилось». Enter = главная кнопка, Esc закрывает. Открытый Lumen установщик закрывает
  сам (место просмотра сохраняется) и заранее об этом пишет. `--silent` работает без окна.
- **Внутри Lumen**: «О программе» показывает «Что нового» и «Версии на этом компьютере» с
  «Вернуться на неё» / «Перейти на неё» (запускает текущий Lumen.exe `--switch-version`: сохранённая
  версия может не знать этой команды, как Inno-бета). После обновления Lumen один раз показывает
  «Что нового в Lumen X» (`ui.json` `lastVersion`; не при первом запуске и не после отката).
  Тексты «что нового» лежат в `src/setup/ReleaseNotes.h`: **при каждом повышении версии в
  `res/app.rc` добавлять запись сверху**.
- **Команды**: `Setup.exe [--silent]`, `Lumen.exe --uninstall [--silent] [--remove-data]`,
  `Lumen.exe --switch-version <версия>`, для тестов `--dir`, `--no-system`, `--automation
  --setup-page <welcome|options|remove|work|done|error>`. Exe из папки установки перезапускает себя
  из `%TEMP%` (свои файлы не заменить), копию удаляет следующий запуск. Установка забирает папку
  Inno-беты: её файлы становятся версией в `versions\`, запись и `unins000.*` Inno удаляются. Файлы
  пользователя в папке (yt-dlp.exe) не трогаются.
- **Проверено**: тесты `setup_*` (73 проверки), весь `core_tests` 57/57. Все экраны сняты в тёмной и
  светлой теме, по-русски и по-английски (скрытые `--automation`-окна). Окно прогнано вживую
  нажатиями: установка → обновление → переключение на сохранённую версию → удаление.
  **Windows Sandbox без окна** (`wsb start`, команды от System, установка в его профиль): Inno-бета →
  новый 0.2.0 поверх (запись Inno и `unins000` убраны, своя запись, ярлык в «Пуске», форматы
  указывают на Lumen) → переключение назад вернуло ровно файлы Inno → переустановка → тихое удаление
  по `QuietUninstallString`: папка, запись, ярлык, ProgID и `RegisteredApplications` убраны, данные
  целы. Сценарий: `%TEMP%\lumen-qa\sandbox-share\inner.ps1`.
  **Не проверено**: окно установщика глазами на обычном экране (кадр появления окна, перетаскивание),

- **Мелочи**: копия деинсталлятора в `%TEMP%` (5,6 МБ) удаляется при следующем запуске установщика,

## 6м. Soak-тест: рост дескрипторов — это модуль NVIDIA (2026-10-22)

Soak 2026-10-21 (113 мин) показал рост дескрипторов ~170 в час (~3,8 за круг), память, GDI, USER и
потоки ровные. Подозрение на открытие .m3u не подтвердилось: в одиночку оно даёт 0 (прошлый замер
поштучных действий принял за утечку прогрев).

- **Причина:** растут только именованные общая память и мьютекс
  `{2627E361-24E2-4F14-99ED-A20D0685D8DD}_v22`. Это имя зашито в `nvspcap64.dll` — модуль захвата
  NVIDIA (оверлей NVIDIA App / ShadowPlay), драйвер подгружает его в каждый процесс с Direct3D. Пара
  остаётся примерно на каждое второе-третье пересоздание видеовывода mpv (видео после песни или после
  остановки): 30 проходов «песня → видео → песня» дали +11 и +17 пар. Полный экран, PiP, превью
  на полосе, переключение песен альбома — 0.
- **Обход проверен и отклонён:** `force-window=yes` после первого видео держит видеовывод mpv живым,
  дескрипторы становятся ровными (16 кругов soak, 1259 без роста). Но, пока после видео играет песня
  или открыта библиотека, процесс держит на ~72 МБ личной памяти, ~60 потоков и ~280 дескрипторов
  больше (D3D-устройство mpv с потоками драйвера). Откачено.
- **Не исправляется намеренно:** ~2 дескриптора на 3 повторных открытия видео и только на ПК с
  оверлеем NVIDIA; даже 1000 таких открытий — ~700 дескрипторов при пределе в 16 млн.
- **Инструмент:** `qa/soak/soak.ps1` теперь сохраняет `handles-<круг>.txt` ([HandleTypes.cs](qa/soak/HandleTypes.cs))
  и пишет в `report.txt`, какие типы и имена дескрипторов и чьи потоки (модуль старта) изменились.
  На машинах с NVIDIA строки `{2627E361…}_v22` — эта известная пара, наклон handles из-за неё
  может помечаться SUSPICIOUS.

## 6и. Полноэкранный режим и смены размера окна без мусора (2026-10-20)

Владелец видел, как при входе в полноэкранный режим и выходе из него окно «бабуется» на несколько
кадров. Записи настоящего экрана (с его разрешения, 4 штуки) и новая съёмка окна показали причины.

- **Выход стоил 4–7 кадров старой картинки, обрезанной по новому окну.** Программа снимала у окна
  стиль рамки (`WS_OVERLAPPEDWINDOW`), а при выходе возвращала его, и DWM заново строил рамку. Теперь
  стиль не меняется: вся площадь окна и так клиентская (`WM_NCCALCSIZE`), а углы, граница и тень
  выключаются атрибутами DWM. Панели задач окно сообщает о себе через `MarkFullscreenWindow`. В
  полноэкранном режиме «Размер», «Переместить» и «Развернуть» из системного меню заблокированы.
- **Выход в развёрнутое окно** раньше шёл так: восстановление, затем снова разворот с анимацией Windows.
  Теперь окно одним движением возвращается на прежний прямоугольник и остаётся развёрнутым.
  Сворачивание и разворот в полноэкранном режиме возвращают на весь экран (`WM_GETMINMAXINFO`).
- **Кадр нового размера рисуется заранее** (`Host::SwitchSizeAhead`, `Surface::BeginAhead`). Смена
  размера начинается сразу после композиции (`DwmFlush`), а `WM_SIZE` подменяет содержимое одним
  commit. Раньше кадр из `WM_SIZE` примерно в половине переключений опаздывал на 1–2 кадра.
  Кадры остальных смен размера (мышью, разворот) показываются сразу (`Present(0)`). На развороте
  исчезло чёрное поле на 2 кадра.
- **Тот же способ** (`Host::ChangeSizeAhead`, без анимации DWM): вход в PiP и выход из него, PiP прямо
  из полноэкранного режима (раньше сначала выход из полноэкранного), подгонка окна под видео и её
  отмена.
- **Обложки и миниатюры** при смене размера пропадали и проявлялись заново: кэш ждал картинку
  другой «корзины» размера. Теперь до прихода новой показывается уже загруженная другого размера,
  а новая подменяет её без проявления (`ImageCache::OtherSize`).
- **Замеры** (`tools/dev/wincap.ps1` + `wincap-stale.py`, кадры неправильной картинки на переключение):
  выход из полноэкранного режима 2–4 → 0 (8 из 8 и 11 из 12 прогонов), PiP из полноэкранного 0–2 → 0,
  разворот и восстановление 0. На настоящем экране вход стал чистым (был 1 кадр), выход 3 → 2 кадра
  ещё до последних двух правок. После них записи экрана не было: разрешённые 4 записи кончились.
- **Осталось:** когда область видео меняется внутри окна (закрыть боковую панель плеера), mpv иногда
  на 2 кадра показывает видео старого размера. Его окно подстраивается к новому размеру само, со своей
  задержкой. Убрать это можно только рисуя видео mpv в композицию Lumen, это отдельная большая работа.
  Изменение размера мышью за край тоже не рисуется заранее: конечный размер неизвестен.
- **Новый инструмент:** `tools/dev/wincap.ps1` снимает невидимое тестовое окно так, как его
  компонует DWM. Он видит то, чего не видит `frames.ps1`. Правило и его ограничения описаны в
  `qa/visual-rules.md`, раздел 3.

## 6з. Запуск с файлом: рамка сразу, картинка проявляется (2026-10-20)

Владельцу не нравилось, как открывается окно при запуске файла: оно появлялось пустым, а через 0,15–0,2 с
приходило всё разом, яркая картинка вместе с панелями за 140 мс. На тяжёлом файле (дольше 0,7 с) сначала
был плеер с чёрной дырой, а картинка потом выскакивала.

- **Рамка плеера с первого кадра окна.** Очередь строится при запуске, видеодвижок не ждём
  (`App::Run` → `Open` до готовности mpv). Поэтому в первом кадре окна уже есть плеер: заголовок с именем
  файла, панель, чёрная область картинки. Песня сразу открывается музыкальным экраном. Удержание
  экрана до первого кадра (`HoldPlayer`) осталось только для открытий из уже запущенного окна.
- **Картинка проявляется из чёрного за 200 мс** (`PlayerView::CoverPicture`), рамка вокруг не меняется.
  Чёрная область лежит под фоном с первого кадра (`MainWindow::PaintBackground`), поэтому в светлой
  теме нет перехода светлый → чёрный.
- **Полоска загрузки.** Если файл открывается дольше 0,3 с (`App::kLoadingLineMs`), по полосе перемотки
  бегает отрезок (`SeekBar::Paint`). Он проявляется и уходит плавно, на быстрых файлах его нет.
  Отсчёт идёт по `App::OpeningSince`. Пока файл открывается, кнопка «пауза» уже горит, время 0:00, в
  заголовке имя файла: при загрузке ничего не меняется.
- **Заглушка песни без обложки** проявляется, когда поиск обложки закончен, как сама обложка.
- **Скорость** (медиана 5 запусков, мс от старта процесса, старая → новая):

  | | окно | рамка плеера | первый кадр | картинка целиком |
  |---|---|---|---|---|
  | видео | 82 → 81 | 286 → 81 | 283 → 274 | 426 → 474 |
  | 4K | 80 → 83 | 277 → 83 | 273 → 275 | 417 → 475 |
  | песня | 81 → 89 | 244 → 90 | — | 384 → 353 |

  Картинка начинает проявляться в то же время, что и раньше, а целиком видна на ~50 мс позже, потому что
  проявление длится 200 мс вместо 140.
- **Проверка кадров** (`tools/dev/frames-check.py`) знает новую схему. Допустимы чёрная область до первой
  картинки, полоска загрузки и картинка, которая проявляется из фона. «Чистый фон» проверяется только там,
  где кадр меняется, а одиночный шаг считается проявлением, только если яркость меняется и дальше.
  Проверено: видео в обеих темах, 4K, песня в обеих темах, папка, несуществующий файл, медленный источник
  (локальный HTTP с задержкой 1,5 с), открытие из запущенного окна.
- **Серый кадр при переходе на видеокарту.** Владелец всё равно видел мигание. Запись настоящего экрана
  (ffmpeg `ddagrab`, 60 кадров/с) показала его: через ~4 кадра после появления окна всё окно на один кадр
  становилось ровным серым. Окно сначала рисуется программным рендером WARP, потом переходит на видеокарту,
  и при этом композиция окна собиралась заново: на кадр Windows показывала голую подложку GDI. Раньше это
  совпадало с пустым фоном и было не видно. Теперь устройство DirectComposition создаётся без привязки к
  видеокарте и переживает переход. Новая цепочка кадров подменяет старую под тем же visual, только после
  своего второго кадра (`Surface::Build`, `Surface::End`, в журнале запуска «device switch: content
  swapped in»). Фоновые серии кадров (`PrintWindow`) этот кадр не видят в принципе.
- **Владелец проверил** двойным щелчком по файлу: не мигает. Финальные замеры (медиана 5 запусков, мс):
  окно 76–80, рамка плеера 76–80, первый кадр 263–288 (песня 132), переход на видеокарту ~210.
- **Не сделано:** плавное появление самого окна. Его рамку и тень рисует Windows, а в фоновых тестах окно
  скрыто, так что этот момент видно только владельцу.

## 6е. Без мигания при запуске и открытии (2026-10-19)

Владелец видел мигание и «недогрузку» при запуске и открытии файлов. Серии кадров показали четыре причины,
все исправлены, владелец проверил видимое окно.

- **Пустое окно до интерфейса.** Окно появляется сразу, с первым кадром GPU (~100 мс от запуска процесса,
  раньше 260–330 мс): это фон темы без белого кадра и скелета. Интерфейс проявляется из фона за 140 мс,
  один раз, когда первый экран готов (данные, картинки, первый кадр файла); предел 400 мс, с файлом
  700 мс. Код: `Host::Reveal`, `Host::ShowContent`, `ContentReady`.
- **Долгое открытие.** Если файл открывается дольше 150 мс, его карточка или строка остаётся нажатой.
- **Заглушки → картинки.** Пока картинка грузится, рисуется пустая карточка, потом картинка проявляется
  за 140 мс.
- **Пустой чёрный плеер.** Текущий экран остаётся до первого кадра mpv, предел 700 мс.
- **Два тоста подряд.** Подсказка с клавишами ждёт, пока уйдёт тост файла.

Инструменты:
- `tools/dev/frames.ps1`: серия кадров с пометкой, что видел бы пользователь;
- `tools/dev/frames-check.py`: вердикт по рывкам.

## 6г. UX плеера (2026-10-19)

- **Стиль текста песен:** Настройки → Аудио → «Тексты песен» и правый клик по тексту. Пять стилей
  (Lumen, как в Spotify, Apple Music, Яндекс Музыке, караоке) и поверх стиля: свой шрифт, размер,
  где поётся строка (сверху, посередине, снизу), сколько строк видно, выравнивание, заливка строки по
  мере пения. Код: `ReadLyricsLook` и `PaintLyrics` в `src/app/player/MusicView.cpp`.
  Заливка идёт равномерно по строке (`Lyrics::SungFraction`): пословные метки enhanced LRC парсер пока
  отбрасывает.
- **Порядок очереди из папки:** `playback.folderOrder`, по умолчанию «Как в Проводнике» — берётся
  столбец сортировки открытого окна Проводника с этой папкой (имя, дата изменения, дата создания,
  размер), без такого окна — по имени. Ещё: по имени в обе стороны, сначала новые/старые, сначала
  большие. Действует на открытие файла, папки и «Следующий файл в папке». В меню сортировки очереди
  добавлены дата и размер. Путь через Проводник проверен только по коду: тестам нельзя открывать
  Проводник.
- **Один файл — одна запись:** `playback.folderAsPlaylist` теперь по умолчанию выключен. Открытый файл
  играет один; карточка следующей серии только предлагает её (без обратного отсчёта и автозапуска).
  Включённая настройка возвращает прежнее поведение.
- **Перетащенная папка** открывается страницей медиатеки (Видео или Музыка, по тому, чего больше), с
  сортировкой и видом; если папки нет в медиатеке, она добавляется (убрать можно как любую другую).
  Файлы и несколько папок по-прежнему сразу играют. Команда для тестов: `drop <путь>`.
- **Место остановки только у видео:** песни всегда начинаются сначала, их позиция не сохраняется, а
  сохранённая раньше не используется (`Player::IsMusic`: `resume-playback=no` при открытии, удаление
  watch-later при уходе). Видео продолжаются, как раньше.
- **Прозрачный текст поверх обложки:** строки текста, название, исполнитель и визуализация на экране
  музыки рисовались серым, заранее смешанным с чёрным, и поверх размытой обложки выглядели мутными
  плашками. Теперь это белый с прозрачностью. Правило и способ искать такие места:
  [qa/visual-rules.md](qa/visual-rules.md), проверка `tools/dev/check-colors.py`.
- **ПКМ на экране музыки** даёт меню плеера без пунктов видео и субтитров, но со «Стилем текста» и
  «Очередью рядом с музыкой».
- **Закреплённая очередь** (`ui.json` → `player.queueDock`: left / right): обложки, название и
  исполнитель, длительность, перетаскивание; закрепить кнопкой в очереди или через ПКМ, открепить
  крестиком. Только для музыки и не в полноэкранном режиме.

## 8. Тестирование и правила

- `tools\dev\launch.ps1 -DataDir <папка> -Fresh [-Library <папка>] [-Settings '{...}'] [-Exe ...] [файлы]`
  запускает изолированный экземпляр с громкостью 0 и печатает PID.
- **Тестовые экземпляры (`--automation`) невидимы:**
  - окна скрыты через DWM cloak;
  - кнопки на панели задач нет;
  - фокус не перехватывается;
  - нет трея, медиаклавиш, системных диалогов, Проводника и записи в реестр.

  Смотреть окно можно только через `tools\dev\capture.ps1`.
- `input.ps1` эмулирует клики, клавиши и текст, с `-Ctrl`/`-Shift`, `-Leave`, `-CaptureLost`, перетаскивание без отпускания (`-Drag ... -Hold`, потом `-Up x,y`). `dump-tree.ps1` выводит дерево виджетов.
- `uia-dump.ps1` печатает дерево UI Automation, то есть то, что видят Narrator и NVDA (роли, имена, состояния); `-Invoke <имя>` нажимает элемент.
- Поиск багов интерфейса: метод и инструменты в разделе 6б; полный прогон —
  `powershell -File tools\dev\sweep.ps1 -Exe <exe> -Out <папка>`.
- Залипания после перетаскивания (превью перемотки, наведение, нажатие, оверлей мини-плеера, ползунок
  громкости, панель, скрытая посреди перетаскивания): `powershell -File tools\dev\check-stuck-hover.ps1 -Exe <exe>`.
- `launch.ps1` принимает только папку данных внутри `%TEMP%` и всегда передавайте `-Library` с тестовой
  папкой: стартовая настройка по умолчанию предлагает настоящую папку «Видео».
- Проверки кода:
  - `python tools/dev/check-icons.py`, `python tools/dev/check-settings.py`, `python qa/i18n_check.py`,
    `python tools/dev/check-colors.py` (непрозрачные цвета поверх картинок, см. [qa/visual-rules.md](qa/visual-rules.md));
  - иконки: SVG в `design/icons`, затем `powershell -File tools/gen-icons.ps1`.
- Тестовые медиа: `bash qa/make-media.sh <короткий путь>`, большая медиатека — `qa/perf/biglib.ps1`.
- Если владелец запустил свой Lumen из `build\Lumen.exe`, файл занят. Тогда собирать с
  `LUMEN_OUT=%TEMP%\lumen-qa\build-main` и его процесс не трогать.

**Правила:**
- мышь и фокус пользователя не трогать;
- закрывать только свои PID;
- не открывать системные диалоги и не менять реестр;
- медиа пользователя не трогать;
- ничего не скачивать и не запускать из интернета;
- Figma bridge (`localhost:3055`) только на чтение;
- компьютер в сон отправлять только по прямой просьбе владельца и только последним шагом;
- сообщения коммитов писать в `.git\MSG` без BOM, коммитить `git commit -F`, заканчивать строкой Co-Authored-By;
- агентам: коммитить после каждого шага и держать тестовые файлы под уникальным префиксом (общие имена в `%TEMP%\lumen-qa` и scratchpad уже приводили к затиранию).
